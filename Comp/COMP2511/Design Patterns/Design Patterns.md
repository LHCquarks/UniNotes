## Overview
Design patterns are proven solutions to common software design problems. They are reusable templates/blueprints which help structure software. It is not a complete implementation, rather a flexible guideline. Design Patterns can be helpful to recognise when a specific problem can be solved by applying a pattern.
**Elements of a Design Pattern**
- Name: Identifier for the Pattern
- Problem: Context and Issue
- Solution: General Design
- Consequence: Results and trade-offs
**Design Patterns v.s. Algorithms**
- Algorithms solve computational problems
- Design Patterns solve design/architectural problems
- Example:
	- Algorithm: Quick-sort
	- Pattern: Strategy to switch sorting algorithms
## Pattern Types
- **Behavioural Patterns**:  Patterns concerned with algorithms and the assignment of responsibilities between objects
	- [[Strategy Pattern]]
	- [[Observer Pattern]]
- **Structural Patterns**: Patterns which dictate the assembly of objects/classes into larger structures compositionally
	- [[Composite Pattern]]
	- [[Decorator Pattern]]
- **Creational Patterns**: Patterns providing various object creation mechanisms - essentially classes which behave as a replacement/intermediary for constructors.
	- [[Factory Pattern]]
	- [[Singleton Pattern and Asynchronous Programming]]
